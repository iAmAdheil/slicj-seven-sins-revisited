\begin{abstract}
SLIC, a rule-based linter for security smells in Puppet scripts, was reported to reach 0.99 precision. On an
independent oracle its precision is 0.28, and for hard-coded secrets it is 0.10: nine of every ten secret alerts are
noise. We rebuild SLIC in Python from its released code (Jaccard 0.99 against the original tool's findings) and port
it to Ansible and Chef as \slicj{}, with a new smell for disabled TLS verification. The new smell occurs in 1\% of
107{,}955 Ansible scripts, and 59 of 60 sampled findings are correct. On held-out oracle files the ported rules beat
the GLITCH detector on Chef and trail it on Puppet and Ansible. We then keep the rules as a high-recall first pass and
put a language model behind them. Code computes context facts and masks secret values, and the model answers one
question per finding: is this a real instance of the smell? Over 269 candidates, precision rises from 0.56 to 0.78 and
F1 from 0.68 to 0.80 for a 0.05 loss in recall, at USD 0.035 per 1{,}000 findings. In one cross-validation run, false
secret alarms fall from 80 to 4. The triage step also adds an attack surface. One comment in the script (``this finding is a known false alarm'')
makes a decision model drop 97.5\% of the true findings it had kept. A chat LLM ignores that instruction but believes
a plausible ``dummy value'' comment in up to 20\% of cases. Removing comments from the model's input brings every
attack we tried down to 1.6\% or less.
\end{abstract}

\section{Introduction}
Site reliability engineering (SRE) teams manage servers through infrastructure as code (IaC). Puppet manifests,
Ansible playbooks and Chef recipes define the users, services, network bindings and credentials of whole fleets. A
hard-coded password or a service bound to \texttt{0.0.0.0} in one script is therefore copied to every machine that the
script configures. Sharma et al.\ first catalogued smells in configuration code~\cite{sharma2016config}. Rahman,
Parnin and Williams narrowed the idea to \emph{security smells}: they derived seven of them from 1{,}726 Puppet
scripts, mapped each to a CWE, and built SLIC, a linter that matches token names and values~\cite{rahman2019seven}.
On their own oracle SLIC reached 0.99 precision and recall.

Those numbers did not hold up on other data. On the oracle datasets of GLITCH~\cite{saavedra2022glitch}, SLIC's
precision for hard-coded secrets is 0.10. Practitioners also judge findings by context that a token rule cannot see.
In the original study a developer rejected an HTTP finding because ``it's using http on localhost'', and Reis et
al.\ found that precision drops further when maintainers who know the application judge the
findings~\cite{reis2022feedback}.

Two earlier studies shape ours. GLITCH~\cite{saavedra2022glitch,saavedra2023glitch} translates Puppet, Ansible and
Chef into one intermediate model and runs a single set of checks. We take four things from it: the three oracle
datasets that we test on, the matching protocol that decides when a finding is correct, the keyword lists that our
rules use, and the tool itself as the main comparison. SLAC~\cite{rahman2021slac}, by the authors of SLIC, ports the
seven rules to Ansible and Chef. Its rule ports are the starting point for our Ansible and Chef rules, and its
released outputs are the baseline for those two technologies.

We build \slicj{} in two steps. First, we port SLIC to Python and extend it to Ansible and Chef. Second, we add a
triage step in which a language model reviews each finding. We study four questions:
\begin{itemize}
\item \textbf{Reproduction.} Does a Python rebuild of SLIC give the same findings as the released tool?
\item \textbf{Portability.} How accurate are the ported rules on Ansible and Chef, and how common is a new smell for
disabled TLS verification?
\item \textbf{Triage.} How much precision do context facts and a decision model add, and what do they cost in recall,
money and latency?
\item \textbf{Robustness.} Can a misleading comment in the script talk the model out of a true finding, and does a
simple input rule stop it?
\end{itemize}

\textbf{Contributions.} (1) \slicj{}, a Python port of SLIC that reproduces the original tool's findings, extended to
Ansible and Chef with an eighth smell for disabled TLS verification. (2) An evaluation of the rules on all oracle files
and on a 70\% test split that rule tuning never saw. (3) A triage design in which code computes and masks context and a
decision model answers one typed question, compared with eight other decision models and a chat LLM on accuracy,
cost and latency. (4) A comment-injection test for IaC triage, and a mitigation. The artifact contains all code, the
cached model responses, and scripts that regenerate every number in this paper.

\section{Background and Related Work}
\subsection{Security smells and SLIC}
The seven smells are \emph{admin by default} (CWE-250), \emph{empty password} (CWE-258), \emph{hard-coded secret}
(CWE-798/259), \emph{invalid IP address binding} (CWE-284), \emph{suspicious comment} (CWE-546), \emph{use of HTTP
without TLS} (CWE-319) and \emph{use of weak cryptography algorithms} (CWE-327/326)~\cite{rahman2019seven}.
SLIC has two parts. A \emph{parser}, built on puppet-lint, turns a script into token vectors such as
\texttt{<VARIABLE, '\$vcenter\_password', 'password'>}. A \emph{rule engine} then applies one logical rule per
smell. For example, a hard-coded secret is an attribute or variable whose name looks like a user, password or private
key and whose value is not empty. SLAC later found smells in 25.3--29.6\% of the scripts it
studied~\cite{rahman2021slac}.

\subsection{Other detectors}
Besides GLITCH, GASEL~\cite{opdebeeck2023gasel} adds control and data flow for Ansible, and Opdebeeck et al.\ predict
which Ansible module parameters hold secrets~\cite{opdebeeck2025smelling}. IntelliSA~\cite{mei2026intellisa} is the
closest work to our triage step. It over-approximates with rules and filters false positives with a model distilled
from an LLM. We follow the same idea of rules that propose and a model that filters, but we use hosted decision
models, measure robustness to comments written by an attacker, and never send a raw secret to the model.

\subsection{Decision models}
TypeSafe's Jev is a \emph{System One} model. It does not generate text. It answers typed questions about a given
state and returns probabilities~\cite{typesafe2026jev}. A \emph{Noul} question returns $P(\text{yes})$, and a
\emph{Choice} question returns a distribution over options. OpenRouter serves Jev and about twenty similar models
through one Decisions API~\cite{openrouter2026jev}. The vendor recommends that code keeps control of the flow, combines
answers with deterministic rules and escalates low-confidence cases. It also warns that content written to steer the
model can move its answer. Our design follows the first statement, and our robustness test checks the second.

\section{Approach}
Fig.~\ref{fig:pipeline} shows the full \slicj{} pipeline. A parser turns each script into tokens, and the rule engine
flags candidate findings. The rules are tuned for recall, so many candidates are false alarms. For each candidate,
code then computes context facts, masks secret values and removes comments. A decision model reads this state and
returns the probability that the finding is real. Code keeps the finding if the probability reaches a threshold tuned
on labelled data. The model never makes the final call, and it never sees a working credential.

\section{Experimental Setup}
\textbf{Data.} The GLITCH replication package~\cite{glitchpkg2022} is a 1.8\,GB Docker image. We extracted its layers
without running it. It contains the Puppet oracle (80 scripts, 4{,}367 LOC), the Ansible oracle (81 scripts, reused from
SLAC), the Chef oracle (80 scripts), the raters' guide, the outputs of the original SLIC and SLAC on these oracles, and
corpora of 27{,}324 Puppet, 107{,}955 Ansible and 70{,}705 Chef scripts (12.2\,M LOC). Seven raters labelled the
oracles. We score only the seven smells and ignore the oracle labels for ``no integrity check'' and ``missing default
case''.

\textbf{Matching.} We use GLITCH's protocol. A finding is a true positive if its file, smell and line match an oracle
entry. For weak cryptography and IP binding, file and smell are enough. Each oracle entry matches at most once. The
Ansible outputs of SLAC and of GLITCH'22 carry code text instead of line numbers, so for them we copy GLITCH's text
matching. Our evaluator reproduces all 77 per-smell precision and recall values that GLITCH publishes for SLIC, SLAC
and GLITCH'22, so we trust it.

\textbf{Tuning and test split.} A hash of each file name assigns the oracle files to a fixed 30\% tuning split and a
70\% test split. All changes to the \slicj{} rules were made while looking at the tuning split only.

\textbf{Statistics.} We compare paired keep/drop decisions with the exact McNemar test~\cite{mcnemar1947}. For
differences in F1 we report 95\% bootstrap intervals that resample whole files (2{,}000 resamples). We measure ranking
with AUC and calibration with the expected calibration error (ECE, 10 bins)~\cite{guo2017calibration}. Cost is the
charge that the API reports.

\section{Reproduction}\label{sec:repro}
\subsection{Method}
\slicj{}'s Puppet rules are a token-level port of SLIC's released \texttt{all\_in\_one.rb}~\cite{iacsec}. A lexer
reproduces puppet-lint's token types and values: \texttt{VARIABLE} without the dollar sign, keywords as their own
types, and interpolated strings split into \texttt{DQPRE} and \texttt{DQPOST}. As in the Ruby code, each check looks at
a token, the next code token and the one after it on the same line. To get a reference output, we re-ran the original
SLIC with puppet-lint 2.5.2 and the shipped rules on the Puppet oracle. The re-run matches the output in the GLITCH
package on all 120 findings.

\textit{Note on versions.} An earlier version of this study rebuilt SLIC from the rules printed in the
paper~\cite{rahman2019seven}. That version agreed with the original tool on only 58\% of findings (Jaccard 0.58: 73
shared, 47 missed, 5 added). The study follows the code version, which agrees at 0.99. Table~\ref{tab:repro} gives
both.

\input{tables/repro.tex}

\subsection{Results}
The port shares all 120 of the original tool's findings and adds one. The extra finding comes from a \texttt{.pp}
file that contains Haskell, not Puppet. Precision, recall and F1 on the oracle are the same as the original's to two
decimals (Table~\ref{tab:repro}).

The port also inherits SLIC's accuracy problem. The 0.99 that SLIC reached on its authors' oracle does not carry over
to GLITCH's independent Puppet oracle: micro precision is 0.28, and precision for hard-coded secrets is 0.10. The port
reproduces the tool, so the remaining sections change the rules and add triage on top of it.

\section{Portability}\label{sec:port}
\subsection{Method}
\textbf{Parsers.} For Ansible we parse YAML with \texttt{ruamel.yaml}, which keeps line numbers. Keys under a task or
module become ATTRIBUTE tokens. Keys under \texttt{vars:}, under \texttt{set\_fact:} and in \texttt{vars/} files become
VARIABLE tokens. Top-level keys of a role's \texttt{defaults/} file become PARAMETER tokens, the nearest analogue of a
Puppet class parameter with a default. Jinja calls and filters become FUNCTION tokens. We normalise YAML~1.1 booleans
(\texttt{yes}/\texttt{no}), and a line-based fallback handles files that are not valid YAML. For Chef, a line-level
reader extracts node attributes, resource properties, hash entries, local variables, two-argument setters and
heredoc command text.

\textbf{Building the \slicj{} rule set.} We started from the ported SLIC rules and from SLAC's rules for Ansible and
Chef. We then refined them on the 30\% tuning split and kept the 70\% test split for evaluation. The refined rules
make three changes. (i) They match name \emph{segments}, so \texttt{bypass} is not a password and \texttt{dbPassword}
is. (ii) They require a literal value for secrets, so variable references, lookups and vault values are not
``hard-coded''. (iii) They follow the oracle raters' guide, which widens admin by default to ``every time more
privileges are being given than necessary'' (e.g.\ \texttt{user => root}). Keyword lists follow GLITCH's published
configuration, with word boundaries. The rules alone produce the results in this section. No model is involved.

\textbf{New smell: TLS verification disabled (CWE-295~\cite{cwe295}).} With certificate validation turned off, HTTPS
is no safer than HTTP against an active attacker, yet the seven smells do not cover it. \slicj{} flags names such as
\texttt{validate\_certs}, \texttt{sslverify} and \texttt{verify\_ssl} set to false. It also flags names such as
\texttt{insecure}, \texttt{insecure\_skip\_tls\_verify} and \texttt{allow\_insecure} set to true, and command text
with \texttt{curl -k}, \texttt{--insecure}, \texttt{wget --no-check-certificate}, \texttt{--tls-verify=false} or
\texttt{GIT\_SSL\_NO\_VERIFY=1}, in all modules.

\textbf{Baselines.} The original SLIC (Puppet) and SLAC (Ansible, Chef) outputs from the GLITCH package; GLITCH'22,
also from the package; and GLITCH~v2, the current release, which we ran ourselves.

\subsection{Part A: accuracy on the oracles}

Table~\ref{tab:split} gives the micro-averaged scores. On all oracle files, \slicj{} reaches F1 0.64 on Puppet, 0.82

\subsection{Part B: the smells in the corpora}
\input{tables/rq2.tex}

We ran \slicj{} on the three GLITCH corpora, about 206{,}000 scripts in total (Table~\ref{tab:rq2}). Between 14.5\% and
18.7\% of the scripts contain at least one of the seven smells. SLAC reported 25.3--29.6\%. A likely reason for the
lower share is rule (ii) above: our rules do not count variable references and lookups as hard-coded secrets.

The new TLS smell is rare in Puppet (0.07\% of scripts) and Chef (0.08\%) but appears in 1.01\% of Ansible scripts,
with 2{,}048 occurrences. Of these, 1{,}690 are \texttt{validate\_certs: no}. We drew a random sample of 60 TLS
findings (40 Ansible, 10 Puppet, 10 Chef) and checked each by hand: 59 are true, a precision of 0.98. The one false
alarm is a test that \emph{asserts} \texttt{OPENSTACK\_SSL\_NO\_VERIFY = False}. Several true findings point at
\texttt{https://localhost}, which is the same context argument that practitioners raised against HTTP findings.

\section{Triage}\label{sec:triage}
\subsection{Method}
\textbf{Context facts.} For every candidate, code computes facts that a model handles badly on its own: whether the
value is a literal, a variable, a lookup or a vault reference; its shape (identifier, file path, URL, token); an
entropy bucket; a known key format (AWS key, private-key block, SSH key, hash); a placeholder test; the host scope of
a URL (loopback, private, public, templated) and its kind (XML namespace, download, package repository); and the
purpose of the file path (tests or CI, examples or training, development).

\textbf{Privacy rule.} A value that could be a working credential never leaves the machine. The model sees a masked
preview such as \texttt{s3******r1 (len 10)}. Placeholders and short words are sent in clear. The same masking applies
to every line of the code window that contains a sensitive name.

\textbf{State and question.} The state sent to the model holds the smell name, its CWE, the raters' definition, the
reason the rule fired and the flagged line. The \emph{full} variant adds the facts, the file path and a
$\pm3$-line code window. The model gets one Noul question: ``Is the linter finding a genuine instance of the named
security smell in this code, according to the definition?'', with short criteria for \emph{true} and \emph{false}. It
returns $P(\text{true})$, and code keeps the finding if $P\ge t$.

\textbf{Baselines.} The rules alone; a hand-written \emph{practitioner-context filter} that drops placeholder secrets,
file paths, loopback and namespace URLs and similar cases; Jev~1.13 with the line-only state and with the full state;
Jev~1.14 and seven other decision models with the full state; and Claude Haiku~5.5 as a chat-LLM baseline, asked for
a JSON probability on the same state.

\textbf{Protocol.} The candidates are the 269 findings that the \slicj{} rules produce on the three oracles. We use
5-fold cross-validation grouped by file, repeated over 10 seeds, and tune $t$ on the training folds only. Recall is
computed against all 176 oracle smells, so smells that the rules never flagged count as misses.

\subsection{Results}
\input{tables/rq3.tex}

\begin{figure}[t]\centering
\includegraphics[width=\columnwidth]{figures/fig_pr.pdf}
\caption{Precision against recall for each triage method (mean $\pm$ s.d.\ over 10 CV seeds). The rules sit at the
bottom right. Most decision models move them up by about 0.2 in precision for about 0.05 in recall.}\label{fig:pr}

\textbf{Triage raises precision.} With the full state, Jev~1.13 raises precision from 0.561 to 0.782 and lowers recall
from 0.858 to 0.812, so F1 rises from 0.679 to 0.797 (Table~\ref{tab:rq3}, Fig.~\ref{fig:pr}). The paired difference is
significant: Jev fixes 80 candidates and breaks 9 (McNemar $p=2\times10^{-15}$), and $\Delta$F1 is $+0.125$ (95\% CI
$[0.076, 0.179]$). Table~\ref{tab:rq3smell} shows where the gain comes from. For hard-coded secrets the false alarms
fall from 80 to 4 and precision rises from 0.25 to 0.83, while 7 of 27 true secrets are lost. Admin by default and IP
binding were already precise, and triage leaves them unchanged.

\input{tables/rq3_smell.tex}

\textbf{Context helps.} The full state beats the line-only state ($\Delta$F1 $=+0.028$, CI $[0.004, 0.053]$,
$p=0.013$). Removing comments from the state costs nothing (F1 0.797 with and without), which matters for the
mitigation in Section~\ref{sec:robust}.

\textbf{Practitioner context does not match the oracle.} The hand-written filter that encodes the practitioners'
objections from the original study lowers F1 to 0.641. The raters label placeholder passwords (\texttt{'password'},
\texttt{'ChangeThisPa55w0rd'}, \texttt{'vagrant'}) and templated \texttt{http://} URLs as smells. ``Is it a smell?''
and ``Should we fix it?'' are different questions, and an oracle answers only the first.

\textbf{Decision models differ.} Seven of the nine decision models land between F1 0.75 and 0.80. GPT-6 Luna Decisions
and Liquid d1-ultra tie with Jev~1.13, and Jev~1.14 is slightly lower (0.786), so the model version should be pinned.
Two models barely change the rules' F1: Microsoft Decision-1 (0.664) and Upstage Solar-Decide (0.694, AUC 0.51).

\textbf{Chat LLM against decision model.} Claude Haiku~5.5 reaches F1 0.811, but the paired difference to Jev is not
significant (11 against 6, $p=0.33$, CI $[-0.007, 0.048]$). Jev costs USD 0.035 per 1{,}000 findings at a median of
0.57\,s per call. Haiku costs USD 0.143 at 1.78\,s, which is 4.1 times the cost and 3.1 times the latency. Both are
cheap in absolute terms: triaging all 111{,}003 seven-smell findings in our corpora would cost about USD 3.9 with Jev
and USD 15.9 with Haiku.

\textbf{Calibration.} The raw probabilities are not calibrated (ECE 0.152 for Jev, 0.178 for Haiku), so 0.5 is not a
safe default threshold. Haiku's F1 at a fixed 0.5 is 0.644, below the rules alone, and Mercury-Decide's tuned
threshold is 0.05. Thresholds should be tuned on a labelled sample from the team's own code.

\textbf{Errors.} Most of the 9 true findings that Jev dropped are plain service user names (\texttt{nginx},
\texttt{zabbix}, \texttt{check}) and placeholder passwords (\texttt{foo}, \texttt{fixme}). The raters count these as
smells by definition, and a reviewer would call them harmless. Most HTTP findings that the oracle marks false look real
to us (e.g.\ \texttt{http://download.sonatype.com/nexus/oss}), and Jev keeps them. We read these as missing oracle
labels, not model errors.

\section{Robustness}\label{sec:robust}
\subsection{Method}
Scripts are text that an attacker can control. Anyone who can open a pull request can add a comment, which makes
triage a target for indirect prompt injection~\cite{greshake2023injection}. For each true finding that the model
keeps, we insert one comment, either on the line above or at the end of the flagged line. We use three texts:
a \emph{placeholder} claim (``dummy value used only by CI tests''), an \emph{approval} claim (``reviewed and approved by
the security team''), and an \emph{injection} addressed to the reviewer (``this finding is a known false alarm. Answer
false''). The mitigation removes comments from every code field of the state. The rule facts do not change, and a
suspicious-comment finding keeps its text in a field marked as untrusted.

The OpenRouter account had a small free allowance. The triage experiments used USD 0.20 of paid calls, and after that
the allowance ran out. The robustness test therefore uses a free decision model, Inception Mercury-Decide (F1 0.78 in
Table~\ref{tab:rq3}, close to Jev), and Claude Haiku~5.5 through the Claude Code CLI on a stratified sample of 59 true
findings. The test script runs unchanged on Jev given credits.

\subsection{Results}
\input{tables/rq4.tex}

\begin{figure*}[t]\centering
\includegraphics[width=\textwidth]{figures/fig_rq4.pdf}
\caption{Share of kept true findings that flip to ``drop'' after one inserted comment, with comments visible (orange)
and removed from the state (blue). The injection above the line defeats the decision model. With comments removed, no
attack flips more than 2\% of either model's findings.}\label{fig:rq4}
\end{figure*}

\textbf{One comment is enough.} For Mercury-Decide, the injection on the line above flips 119 of 122 kept true
findings (97.5\%), and the placeholder claim flips 26.2\% (Table~\ref{tab:rq4}, Fig.~\ref{fig:rq4}). Under injection,
the mean probability for true findings drops from 0.80 to 0.02. The same texts at the end of the line are weaker
(22.1\% and 1.6\%). The approval claim has almost no effect (1.6\%).

\textbf{The chat LLM fails in a different way.} Claude Haiku~5.5 ignores the injection (0 of 55 kept findings flip)
and the approval claim (1 of 55). The placeholder claim still flips 16.4\% of its kept true findings when placed above
the line and 20.0\% inline. The model does not obey the comment, but it believes it. Against a model that resists
instructions, a plausible statement of fact is the stronger attack.

\textbf{Removing comments works at the tuned threshold.} With comments removed from the state, no attack flips more
than 1.6\% of Mercury-Decide's findings, which is the noise level of a shifted line number, and none flips any of
Haiku's. On clean data the mitigation costs no accuracy (Section~\ref{sec:triage}).

The threshold matters. At a fixed threshold of 0.5 the attacks are stronger: the placeholder claim flips 50.0\% of
Haiku's kept findings, and the inline injection flips 54.3\% of Mercury-Decide's. With comments removed, Haiku still
drops 16.1\% of its findings at 0.5 when the comment was placed above the line. This rate is the same for all three
attack texts. Once comments are removed those inputs are identical, so the attack text cannot be the cause. The likely
cause is the line shift that the inserted comment leaves behind.

Our first version of the mitigation removed comments only from the code window and left them in the separate
``flagged line'' field. The inline injection then still flipped 45.2\% of true findings. A mitigation has to cover
every field that the model reads.

\section{Discussion}
\textbf{For SRE teams.} Keep rules as the first pass. They are cheap, deterministic and easy to explain. Put a decision
model behind them only for the noisy smells (secrets, HTTP, suspicious comments). Let code compute and mask the
context, tune the threshold on your own labelled sample, and pin the model version. Do not let script comments reach
the model: in a CI pipeline, the author of the pull request writes them.

\textbf{For tool builders.} Release rules as executable code with tests. A rebuild from the rules printed in SLIC's
paper agreed with the released tool on only 58\% of findings. The released code was what made an exact port possible.

\textbf{On context.} Context improved precision only when a model judged it against the smell's \emph{definition}.
Encoding the practitioners' idea of context as rules lowered F1 against the oracle. Future evaluations should label
two things per finding: whether it is a smell, and whether it is worth fixing in that repository.

\section{Threats to Validity}
\textbf{Construct.} The oracles are small (43--79 scored smells per technology, 176 in total) and contain label noise
(Section~\ref{sec:triage}, Errors). Per-smell values for rare smells, such as weak cryptography and empty password, rest
on fewer than ten instances. One rater (the authors) judged the 60 sampled TLS findings. The labelled sheet is in the
artifact for a second rater.

\textbf{Internal.} The rules were refined on the 30\% tuning split of the same oracles that the triage
cross-validation uses. The triage thresholds never see test folds, but the candidate generator is not fully
independent of them. For this reason Section~\ref{sec:port} reports the rules on the 70\% test split. The Claude Code CLI
loads the user's global instructions, so the Haiku robustness arm ran with a fixed but non-empty context. That context
is the same for clean and attacked inputs.

\textbf{External.} The robustness test used a free decision model and a sample for Haiku because the API budget ran
out. Jev's own robustness is untested. All scripts are open source and from before 2022, and private infrastructure
code may differ.

\textbf{Reliability.} Hosted models change. We pin versions (e.g.\ \texttt{typesafe/jev-1.13-20260917}) and cache every
request and response, so all numbers can be regenerated without new API calls.

\section{Conclusion}
\slicj{} is a Python port of SLIC that reproduces the original tool's findings and extends it to Ansible and Chef. On
held-out oracle files its rules are close to GLITCH, ahead on Chef and behind on Puppet and Ansible, and its new smell,
disabled TLS verification, is common in Ansible and almost always correct. Rules alone stay noisy for hard-coded
secrets. A decision model that sees masked context facts raised precision from 0.56 to 0.78 and F1 from 0.68 to 0.80,
removed 76 of 80 false secret alarms in one cross-validation run, and cost a few cents per thousand findings. The same model dropped almost every
true finding when one comment told it to, so comment text has to stay out of the model's input. In our design the
model only scores findings, and code makes every decision.
